## 2. Recommended Phased Remediation Waves

### Wave 0 — Immediate Pre-Launch Blockers (Estimated Effort: ~1 Day)
Resolves all **CRITICAL** and security/access **HIGH** blockers before any real user onboarding:
1. **`AUD-001` (CRITICAL):** Fix provider withdrawable balance calculation (exclude `cash_on_completion` from platform-held balance) and enforce withdrawal caps.
2. **`AUD-002` (CRITICAL):** Lock `firestore.rules` booking creation to `paymentMethod == 'cash_on_completion'` and `paymentStatus == 'pending_cash'`; hide simulated CMI escrow UI controls.
3. **`AUD-003` (HIGH):** Enforce `accountStatus != 'suspended'` in `firestore.rules` (`isVerifiedUser()`) and `src/app/guards/RouteGuards.tsx`.
4. **`AUD-004` (HIGH):** Fix `handleSaveProfile` and `saveFullProviderCard` in `useMarketplaceAuth.ts` + `firestore.rules` so saving a profile never fails with `PERMISSION_DENIED` when `accountStatus`, `termsAcceptedAt`, or `completedJobs` is present.
5. **`AUD-005` (HIGH):** Restrict `/notifications` creation in `firestore.rules` so non-admins cannot spoof `'kyc_updated'`, `'dispute_resolved'`, or `'system'` notifications.
6. **`AUD-009` (HIGH):** Add `@grpc/grpc-js: "^1.13.6"` override in `package.json` to clear all 4 `npm audit` High vulnerabilities.

### Wave 1 — Core Workflow & Data Integrity Hardening (Estimated Effort: ~1 Day)
1. **`AUD-006` (HIGH):** Enforce `/providerAvailability` and `/scheduleLocks` in direct bookings (`submitBooking`) and reschedules (`rescheduleBooking`), and delete `/scheduleLocks/{lockId}` upon booking cancellation/rejection.
2. **`AUD-007` (HIGH):** Allow providers to revise and re-submit withdrawn/pending proposals in `firestore.rules` and `useJobPosts.ts`.
3. **`AUD-008` (HIGH):** Unify booking-card chat actions with `/messages/:bookingId` (`useMessaging`) so `/conversations` and `/notifications` always stay in sync.
4. **`AUD-010` (HIGH):** Remove hardcoded fallback phone numbers (`+212661428910`, `+212661000000`).
5. **`AUD-015` (MEDIUM):** Remove the `"Joindre photo chantier témoin"` demo photo button from `BookingModal.tsx` in production.

### Wave 2 — Compliance, CI Storage Deployment & Privacy (Estimated Effort: ~1 Day)
1. **`AUD-011` (MEDIUM):** Persist `termsAcceptedAt: serverTimestamp()` on `/users/{uid}` at registration/onboarding.
2. **`AUD-012` (MEDIUM):** Add `storage.rules` to `.github/workflows/firebase-deploy.yml` after granting `roles/firebasestorage.admin`.
3. **`AUD-013` (MEDIUM):** Auto-reject competing pending proposals and notify bidders when a quote is accepted.
4. **`AUD-016` (MEDIUM):** Enforce Firebase App Check (`VITE_FIREBASE_RECAPTCHA_SITE_KEY`) and mask public provider phone numbers until user interaction.

### Wave 3 & Wave 4 — Scalability, Modularization, i18n Consolidation & Emulator E2E
1. **`AUD-014`, `AUD-017`, `AUD-018`, `AUD-019`, `AUD-020`, `AUD-021`:** Split oversized dashboard files, migrate inline `isAr` strings into `translations.ts`, switch landing page providers query to paginated `getDocs`, add modal focus trapping and `Africa/Casablanca` date formatting, and add live Firestore Emulator tests.
